# 0004. AGENTS.md 逐角色不對稱，worker 不知道驗收判準

日期：2026-09-04
狀態：已採用

## 背景

Agent 行程從家目錄啟動，`config.toml` 不提及 `/workspaces`，
也沒有任何環境變數指向它。**掛載存在不等於 agent 知道它存在。**

Chart 支援 `agentsMd`：內容渲染進 ConfigMap，
掛載成 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`，
正是各家 coding CLI 讀取指示的位置。

內容由 renderer 從 catalog 產生，因此不可能與實際掛載脫節。
但接著出現一個問題：**每個 agent 該知道多少?**

## 決策

每個 agent 只拿到**自己那一側**的協定：

| 角色 | 被告知 | 不被告知 |
| --- | --- | --- |
| leader agent | 派工流程、完整驗收閘門清單 | — |
| worker | 只接受 leader 提及、回報對象、自己的職責 | 驗收閘門的判準 |

Worker 知道閘門存在（那是它不該 push 的原因），
但不知道**什麼能滿足閘門**。

## 後果

**得到**

- Worker 無法對「它本來就該拒絕的指令」進行合理化推理。
  一個知道驗收需要哪些欄位的 worker，比較容易被說服去湊齊它們。
- 每個檔案較短，與該角色實際能做的事對應。

**付出**

- Worker 較難自行判斷回報是否足夠，可能需要 leader 多次往返。
- 兩份內容需分別維護（由同一份程式碼產生，但邏輯分支不同）。

## 替代方案

**所有 agent 拿到相同內容** — 被否決。
在「內容不可信」的威脅模型下，把驗收判準交給每個 worker，
等於把繞過閘門所需的資訊一併交出去。

**完全不給 worker 流程資訊** — 被否決。
Worker 至少必須知道只接受 leader 的訊息、以及回報對象，
否則它會接受人類在頻道裡的直接指令。
